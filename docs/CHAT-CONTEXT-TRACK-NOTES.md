# Chat context integration notes

1. Scope: Python-only question-matched evidence builder. No provider/LLM calls were made during verification. No client, shared-contract, conversation-route or assistant files were changed in this track.
2. Interface: `await build_context(app, get_chart, conversation, message, timeframe, now=None)` returns `(context, citations, last_bar)`. The first citation belongs to the selected interval. The latest provisional bar may be returned for display while being excluded from every calculation. Top-level timeframe, provenance, indicators and capabilities remain available for existing consumers.
3. Inputs and storage: `conversation.signal` is an immutable original Signal or null. `conversation.chart_start/end` are dated chart selection markers. If present, `store.get('conversation_charts', conversation.id)` must contain a ChartResponse. It is filtered to finalized bars known at signal availability before signal-time indicators are calculated. Outcome lookup uses the original signal ID and excludes future evaluation/resolution times. It never rescales confidence or chooses a favorable ambiguous result.
4. Quantitative review: known-bar filtering precedes EMA/RSI/ATR calculations. Session high/low labels require complete aligned five-minute coverage against XNYS; a twenty-bar observed range remains an observed range. Scenario confirmation/invalidation uses supported boundaries, withholding a current preference for stale data. A qualitative EMA alignment is not a calibrated probability. Original targets stay attributed to the historical signal.
5. Feed and cost review: all retrieval explicitly requests IEX. Volume is omitted from bar evidence; capabilities remain disabled with needs SIP data. The SPY illustrative long-only cost cases are assumed full spreads of $0.01/$0.02/$0.05, one reference share, one day, 1bp slippage per endpoint, zero commission/impact. There is no consolidated liquidity inference. Unverified charge dates and unspecified non-SPY assumptions return reasons.
6. Calendar and security: exchange_calendars 4.13.2 supplies holidays, early closes and DST. No credentials or network hosts are introduced by this module. News summaries are untrusted attributed evidence. Context is bounded to 23KB; less essential bar detail is reduced first, then oversized evidence fails explicitly. Root integration should also budget optional conversation summary and history before provider dispatch.
7. Verification: 23 deterministic tests pass, including all six fixed evaluation questions. Existing dependency deprecation warnings concern NumPy generic timedelta handling inside exchange_calendars. No model behavior, Render deployment, browser/device behavior or real-data latency is claimed verified by this track.
8. Decisions: keyword-matched retrieval selects the requested interval plus 5m; next-session/setup/comparison questions additionally request 1h and 1D. Up to 240 five-minute bars and 120 other-interval bars are fetched; only twelve most recent finalized bars per interval enter context initially. Quantitative summaries operate on the full bounded window. No arbitrary model data-fetch tool or retraining is added.
