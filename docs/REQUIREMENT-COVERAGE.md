# Requirement coverage

Source review dated September 9, 2026. This is a coverage assessment, not a declaration that Waves 0–5 have all passed acceptance. It compares [the accepted scope](../IMPLEMENTATION.md), the user's detailed research-only implementation instructions, and [the original plan](../plan.md) where not superseded. Integration and final verification were still running when this file was written; the final review and recorded test output take precedence for exact test counts.

**DONE** means the bounded behavior named in that row exists, with the cited implementation and verification mechanism. It does not imply every related feature or external acceptance has passed. **PARTIAL** means code or required coverage remains unfinished. **EXTERNAL** means an account, entitlement, deployment environment, or physical device must supply the remaining evidence. An unavailable input does not make an unfinished integration complete.

Execution, simulated fills, broker state, execution configuration, and automatic scheduled retraining from the earlier plan are explicitly superseded and are not missing deliverables. The required identity remains: **“Selery is research software that displays analysis. It does not execute, recommend, or place trades.”**

## Most consequential gaps

1. **Acceptance evidence:** no real-iPhone gesture/performance/push acceptance, verified Vercel/Railway deployment, signed TestFlight build, or complete Docker topology evidence. Local builds and headless tests do not substitute for these.
2. **Requested breadth exceeds the shipped thin slice:** advanced strategies, alpha evaluations, ETF/options context, the full chart catalog and provider ingestion are unevenly exposed through services, HTTP and UI. Several useful Python methods need data acquisition and product integration.
3. **Historical and ML claims need longer qualified data:** fixtures cannot establish crisis robustness, crowding comparisons or a successful calibrated model. Sequence production serving and full SHAP/validation visualization remain incomplete.
4. **Production durability and contract completeness:** process-local auth coordination, provider/version bar identity, unfinished compact mobile schemas, dynamic endpoint responses and incomplete operational monitoring require further work before broadening deployment.
5. **Release audit and gate completeness:** exhaustive file-level source review, packaged third-party notices, hosted CI and final boundary review records are not implied by an inventory or a successful local build.

No entire wave should be called fully accepted on the basis of this document. Implemented research workflows are usable within their documented fixture/live-feed limits; pending code and external evidence remain explicit above.
